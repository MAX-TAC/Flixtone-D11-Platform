## 4. Критическая развилка: «брат-близнец» с 1 HDMI и без ToF

**[P]** Судя по всем материалам, это отдельный SKU **8052** (Everycom CineLux 1 HDMI), а не «урезанный 8054».

Что доказано статически **[F]** (анализ заводских PKG в `Everycom-Cinelux-Firmware`):

- 8052 и 8054 — одна платформа `mt5873_cd`, Android 13/API33, одинаковый GPT, **побайтово совпадающий публичный AVB RSA-4096 ключ**, все 207 DTBO совпадают по SHA (но порядок записей в `dtbo_mapping.ini` другой — загрузчик может выбирать по индексу).
- Профильные отличия: `HW6:HDMI` + `port.count=1` против `HW6:HDMI1,HW7:HDMI2` + `port.count=2`; `support.toffunction` 0/1; autokeystone 0/1; разные OTA-каналы.
- 57,5 % путей EROFS побайтово равны; различаются 4 ELF из 1245; у 8054 есть `KuSetupWizard`, `libfactoryi2c_jni.so`, `libsettingsi2c_jni.so`.
- **Кросс-прошивка не безопасна**: `boot_a`, `dtbo_a`, `mboot_a`, `optee_a`, `tvconfig_a`, `tvservice_a`, `factory_a_a`, `project_id`, `persist`, `vbmeta_a` различаются по SHA.

Практические следствия:

1. Если близнец — 8052, то весь текущий MOD **нельзя** ставить как есть: в коде жёсткие гейты по `machine.id == 8054` (`ProjectorCompatibilityPolicy`), а разделы «Проекция» содержат ToF-функции (обнаружение препятствия, авто-выравнивание), которых на близнеце физически нет.
2. Нужен **отдельный экземпляр сборки** (или хотя бы runtime-профиль) для его machine id, свой список доступных пунктов, своя проверка HDMI-портов.
3. Для близнеца нужен **свой дамп** (`super.img` + `boot/mboot/uenv/vbmeta/tvconfig/persist` и т.д.), иначе отката нет.

**Без точного `getprop ro.rjpj.machine.id` близнеца дальше проектировать нельзя.** Это первый вопрос, который надо закрыть.

## 6. MOD TvSettingsPlus: архитектура и что реально работает

### Как он встроен **[F]**

- Патч `tools/patch_8054_mainsettings.py` вставляет в `MainFragment.onCreateView` вызов `StockMainSettingsMenu.install(...)` **до** `invoke-super`, с проверкой сигнатуры/единственного возврата.
- `StockMainSettingsMenu` создаёт свою `PreferenceCategory`, берёт заголовок/order у штатной `general_settings`, добавляет 8 строк и **скрывает** все остальные корневые.
- Wi-Fi и «Приложения» делегируются штатным `connectivity.NetworkActivity` и `device.apps.AppsActivity`.
- Свои экраны: `NativeSections.Page extends SettingsPreferenceFragment` (все вызовы в `guarded()`), 20 Activity-обёрток по 5 строк над `ModSettingsActivity extends TvSettingsActivity`.
- Остальные штатные экраны (дата/время, язык, аккаунты, хранилище, безопасность, доступность, разработчик) делегируются через `ComponentName`.

### Инвентарь по 8 разделам **[F]**

| Раздел | Статус | Механизм |
|---|---|---|
| Wi-Fi и сеть | делегировано стоку | `NetworkActivity` |
| Bluetooth | частично | `NativeBluetoothPage`; включение через `adapter.enable()` под гейтами, **выключение намеренно заблокировано** |
| Источники | реализовано | `TvInputManager` + `ACTION_VIEW` в `com.mediatek.wwtv.tvcenter`; boot — `persist.trd.source_id`; autoplay — `persist.rjpj.hdmiplug.autoplay`; EDID — **read-only** (гейт «только 8052») |
| Проекция | реализовано с гейтами | яркость — broadcast `com.action.brightReceiver` + `persist.bright.model`; фокус — `persist.rjpj.autofocus.poweron/move`; move-keystone — `persist.rjpj.autokeystone.move` только при трёх нулях |
| Изображение | **read-only** | 12 ключей `Settings.Global` показываются; `OemPictureState.mayEdit()` → `false`; запись есть в коде, но закрыта |
| Звук | частично | профиль `sound_style`; **5 полос EQ реально пишутся** в User-профиле с readback; звук кнопок; задержки speaker/SPDIF; выход — штатный `AudioOutputActivity` |
| Приложения | делегировано стоку | `AppsActivity` |
| Устройство | смешанно | температура только чтение; AC-boot через `MtkUtil`; таймер — OEM; `font_scale`; **сон/заставка принудительно отключаются** на BOOT |

## 7. Почему «вырезать мусор» сейчас нельзя

Доказанная кодовая зависимость **[F]/[D]**:

```
com.my.settings (KuSettings)
  BootupReceiver (BOOT_COMPLETED)
    → MySetTimeService (TIME_TICK, 1 мин)
    → com.coolux.source/.service.TimeService  (охлаждение/вентилятор, источники, термо)
```

На живом устройстве оба сервиса реально работали (`TimeService` uid 1000, `startRequested=true`; `MySetTimeService` перезапущен на ~19 с позже) **[D]**. Обратных ссылок `KuSourceRJ → com.my.settings` нет **[F]**, но обратное направление есть и оно критично.

Дополнительно **[F]**:

- `xtzm_setting.txt`: `"settingApps": ["com.my.settings"]` — потребитель не найден.
- OEM `SetupWizard`/`Provision` и `WFDSinkTest` ссылаются на `com.my.settings`.
- Мод-код `KuSourceRecoveryActivationPolicy.automaticRecoveryAllowed` возвращает `true` **только для 8052**, а `KuSourceRecoveryBootReceiver/Service` объявлены `enabled=false` → на 8054 замена watchdog **недостижима двумя независимыми гейтами**. Отсюда `SYS03 = BLOCKED_SAFETY`.
- `OemProjectionPanel.projectionIntent()` на 8054 **до сих пор** открывает `com.my.settings/com.my.settings.activity.ProjectionActivity` — это прямое противоречие цели «без китайского UI в пользовательском пути» (в `docs` заявлено обратное).
- Кнопка **Settings** на пульте (`keyCode 307`) перехватывается системной политикой `TrdTvWindowMangerImpl` → `trdservice` → `FloatMenuService` (`APPLICATION_OVERLAY`), а не implicit-intent'ом. `activity-alias` на `android.settings.SETTINGS` этого не ловит (проверено в R5, откатано в R7).

Вывод: удаление `KuSettings`, `KuSourceRJ`, `zxlauncher`, `zxstore` без переноса watchdog/термо/пульта = риск перегрева, потери пульта и цикла загрузки.

**Шаг 3.** Разрешения — минимально необходимые:

| Permission | Уровень | Зачем |
|---|---|---|
| `Contents` | Read and write | push веток/файлов |
| `Pull requests` | Read and write | создавать/обновлять PR |
| `Workflows` | Read and write | **обязательно**, если я буду менять `.github/workflows/*` (без него push таких файлов отклоняется) |

## 11. ADB с командной строки вашего ПК: что возможно

### Технически — да

- `adb.exe` версии **37.0.1** есть: `C:\Program Files\platform-tools\adb.exe`. (На PATH стоит `C:\WINDOWS\system32\adb` — это **0-байтная заглушка**, из-за неё скрипты диагностики и падали с «Cannot run a document in the middle of a pipeline».)
- ПК в той же подсети, что и проектор: Wi-Fi `192.168.31.144/24`, шлюз `192.168.31.1`; маршрут `192.168.31.0/24` есть.
- Проектор уже был прописан в adb: `192.168.31.99:5555` (`product:mt5873_cd`, `model:Projetor`).
- Встроенный в эту сессию `adb`-инструмент нерабочий (в его окружении нет adb-клиента), поэтому я использую ваш `adb.exe` напрямую — это работает.

### Что сейчас мешает

Проектор **не отвечает**: `ping` → «transmit failed», после `kill-server` список устройств пуст, старая запись `offline` была мусором от прошлой сессии. Скорее всего проектор выключен или ушёл в сон/сменил IP.

Чтобы продолжить, нужно:

1. Включить проектор и дать ему выйти в сеть (Wi-Fi или Ethernet к тому же роутеру).
2. Убедиться, что отладка по сети включена (на 8054 она уже была включена — в свойствах видно `persist.sys.usb…func=adb`).
3. Сказать мне «включил» — я выполню `adb connect 192.168.31.99:5555` и проверю `getprop ro.rjpj.machine.id`.
4. Если IP изменился — назовите новый (виден в роутере или в «О проекторе» на самом проекторе).

### Что я предлагаю снять первым (только чтение, без изменений)

```
getprop ro.rjpj.machine.id / ro.build.fingerprint / ro.rjpj.hdmi.ports / port.count
getprop ro.boot.vbmeta.device_state / verifiedbootstate
dumpsys activity services | grep -E "coolux|my.settings|trd"
dumpsys tv_input            # соответствие HW6/HW7 ↔ port_id
dumpsys hdmi_control        # CEC/ARC
dumpsys media.audio_policy  # активный маршрут
dumpsys display / SurfaceFlinger | head   # 1080p overlay, режимы
cmd package list packages -f
```

Это закроет часть P0-вопросов (HDMI-порты, CEC/ARC, активный аудиовыход, реальный HOME-resolver) без единой записи в систему.

### Правила, которые я соблюдаю

- **Чтение — свободно** (getprop, dumpsys, pm list, logcat, screencap, uiautomator).
- **Любая запись — только после вашего явного «да» на конкретную команду**: `settings put`, `pm install/uninstall/disable`, `am start` (меняющий состояние), `input`, `reboot`, `svc`, `cmd`.
- **Никогда**: `fastboot flash/erase/lock`, `dd of=/dev/block/*`, `pm clear`, factory reset, запись `persist/eeprom/private/tvconfig/mboot`.
- **ADB наружу не публиковать.** Порты вида `45912 → 5555` в интернет — плохая идея: ADB даёт полный контроль, нестандартный порт защитой не является. Работаем либо в вашей LAN, либо через VPN с ACL.
