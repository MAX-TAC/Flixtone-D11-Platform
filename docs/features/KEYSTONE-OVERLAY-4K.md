# Оверлей фокуса и трапеции: почему мыльный и как починить

Дата: 2026-11-24. Уровень: `DEVICE_VERIFIED` (проблема) + `ASSUMPTION` (причина и решение).

---

## 1. Что видит владелец

При регулировке фокуса и трапеции на экране рисуется оверлей (сетка, стрелки,
индикаторы моторов). **Выглядит как 720p** — крупные пиксели, мыльные линии и шрифт.

## 2. Причина (гипотеза, но очень вероятная)

Из `dumpsys display`:

```
mBaseDisplayInfo:    real 3840 x 2160, density 640 (320 dpi)
mOverrideDisplayInfo: real 1920 x 1080, density 320 (160 dpi)
mCurrentLayerStackRect = Rect(0,0 - 1920,1080)
mCurrentDisplayRect    = Rect(0,0 - 3840,2160)
```

Android-слой рисуется в буфер **1920×1080** и аппаратно растягивается на **3840×2160**.
Всё, что рисуется в этом слое, включая оверлеи, — мылится вдвое.

**Дополнительный фактор:** оверлей рисует `com.trd.service` (`UICtrlImpl`,
`autokeystone_view.xml`, `rj_focus_dialog.xml`). Судя по названиям ресурсов, это
**собственные View с фиксированными размерами** в `dp` — а `dp` при density 320
дают крупные элементы, которые при растягивании на 4K выглядят грубо.

## 3. Три возможных решения (по возрастанию сложности)

### Вариант A — поднять логическое разрешение Android

```
wm size 3840x2160
wm density 640
```

- Плюс: оверлей станет резким сразу, без правки APK.
- Плюс: заодно решает «мыльный» UI всего Android.
- Минус: нагрузка на GPU ×4, возможны просадки FPS.
- Минус: элементы станут физически мелкими (нужна проверка на 10-футовом UI).
- **Риск: средний.** Возврат: `wm size reset`, `wm density reset`.

### Вариант B — перерисовать оверлей в 4K

Правка `UICtrlImpl`/layout в `com.trd.service`: заменить фиксированные размеры на
векторные drawable и пропорциональные размеры.

- Плюс: точный контроль над оформлением (можно сделать красиво).
- Минус: нужен исходник или разбор smali, и тест на устройстве.
- **Риск: средний** — можно сломать отрисовку.

### Вариант C — свой оверлей в MOD

Нарисовать собственный оверлей в нашем приложении поверх OEM-регулировки.

- Плюс: полный контроль, можно сделать в стиле Android TV.
- Минус: надо синхронизироваться с движением моторов (`IMotorCtrl` через `trd.framework`).
- Минус: самая большая работа.

## 4. Рекомендация

**Сначала A (дешёвый тест), потом B или C по результату.**

Причина: если `wm size 3840x2160` + `wm density 640` даёт резкий оверлей и не убивает
производительность — проблема решена одной командой, без правки APK.

Если оверлей остаётся грубым (потому что нарисован маленькими картинками) — только тогда
идём в B/C.

## 5. Порядок проверки (требует согласия на записи)

```
1. Зафиксировать текущие значения:  wm size  /  wm density
2. Зафиксировать FPS: dumpsys gfxinfo com.android.tv.settings framestats  (до)
3. Открыть регулировку фокуса, снять скриншот  (до)
4. wm size 3840x2160 ; wm density 640
5. Повторить пункты 2 и 3  (после)
6. Откат: wm size reset ; wm density reset
```

**Откат обязателен** — без него устройство останется в изменённом режиме.

## 6. Связь с общей задачей «мыльный UI»

Это та же проблема, что описана в журнале (`research/device-slices`): весь Android-слой
на проекторе — 1080p при панели 4K. Оверлей — лишь самый заметный её симптом.

**Поэтому решение по оверлею должно приниматься вместе с решением по всей системе:**
если поднимаем весь UI до 4K — оверлей починится сам. Если не поднимаем — надо
перерисовывать оверлей отдельно.
