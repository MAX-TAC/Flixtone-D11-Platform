# TvSettingsPlus — полная документация доработок

Версия документа: 2026-11-27
Относится к APK: `TvSettingsPlus-8054-2.28-MAINSETTINGS.apk` (versionCode 228)
Базовое приложение: заводской `com.android.tv.settings` прошивки 8054 (Android 13, `mt5873_cd`)

---

## 1. Что это и зачем

Заводское приложение настроек проектора FlixTone D11 (8054) содержало:

- **три параллельных мира настроек** — Android TV Settings, OEM-надстройка `com.trd.*`, и `KuSettings`;
- **десятки экранов**, недоступных из меню или ведущих в пустоту;
- **функции без аппаратной поддержки** — DVB-тюнер, беспроводные колонки, витринный режим;
- **дубли** — один и тот же параметр в 2–3 местах с разными значениями.

Цель доработки — **одно приложение настроек**, в котором все параметры проектора
(изображение, звук, коррекция, источник, питание) находятся в одном месте,
работают и не дублируются.


### 2.2 Структура кода (Projector-Soft)

```
app/tvsettingsplus-mod/
  src/exact8054/java/dev/projectorsoft/tvsettings/   ← ЭКРАНЫ НАСТРОЕК (собирается в APK)
  src/main/java/dev/projectorsoft/tvsettings/        ← логика, политики, хуки
tools/                                               ← скрипты сборки и проверок
.github/workflows/build-tvsettingsplus-8054-audit.yml ← СБОРКА
```

**Важно:** APK собирается **только** из `src/exact8054/java`. Файлы из `src/main/java`
попадают в APK как зависимости, но экраны описаны в `exact8054`.

### 2.3 Как собирается

Сборка полностью в GitHub Actions, локально ничего не нужно:

1. `workflow_dispatch` или push в `mod/v41-bt-eq-gamemode`
2. Workflow `Build exact 8054 TvSettingsPlus audit candidate`
3. Шаги:
   - скачивает **живую прошивку 8054** и распаковывает заводской APK (только чтение)
   - собирает Java-код (`exact8054` + `main`)
   - прогоняет ~20 JVM-тестов политик
   - декодирует заводской APK через apktool
   - патчит `MainSettings` (smali) и манифест (AXML)
   - **вырезает мусорные Activity** из манифеста
   - собирает итоговый APK
   - подписывает **платформенным ключом** (`c8a2e9bc...`) — иначе система не установит
   - загружает артефакт

4. Скачать: страница запуска → раздел **Artifacts** → `tvsettingsplus-8054-<версия>-mainsettings`

### 2.4 Нумерация версий

- `versionCode` — монотонный: 200, 201, … 228, …
- `versionName` — всегда `1.0`
- список допустимых versionCode — в `tools/compose_brightness_v3_apk.py` (сейчас до 240)
- **при добавлении новой версии нужно расширять этот список**, иначе сборка упадёт

## 4. Экраны детально

### 4.1 Bluetooth

| Пункт | Тип | Что делает |
|---|---|---|
| **Bluetooth** | переключатель | Включает/выключает адаптер. Включается **сразу**, без диалога подтверждения |

### 4.2 Источники

Две группы.

**Группа «Выбор источника»:**

| Пункт | Тип | Что делает |
|---|---|---|
| **Android TV** | действие | Запускает **реальный лаунчер** (не FallbackHome нашего пакета) |
| **HDMI 1** | действие | Открывает вход HDMI 1. **Неактивен**, если сигнала нет |
| **HDMI 2** | действие | Открывает вход HDMI 2. **Неактивен**, если сигнала нет |

Подпись под HDMI: «Подключен» / «Нет сигнала» / «Нет подключения».

**Источник при включении** (отдельно, между группами):

| Пункт | Тип | Что делает |
|---|---|---|
| **Источник при включении** | список | Android TV / HDMI 1 / HDMI 2. Пишет в `persist.trd.source_id`. По умолчанию показан **Android TV** |

**Группа «Дополнительные настройки»:**

| № | Пункт | Тип | Ключ | Что делает |
|---|---|---|---|---|
| 1 | **HDMI-CEC** | переход | — | Отдельный экран (см. 4.8) |
| 2 | **HDMI ARC** | переключатель | `hdmi_arc_control_enabled` | Возврат звука на ресивер по HDMI |
| 3 | **Автопереключение HDMI** | переключатель | `persist.rjpj.hdmiplug.autoplay` | При появлении сигнала переключаться на этот вход |
| 4 | **Совместимость HDMI (EDID)** | список | `tv_input_hdmi_edid_version` | HDMI 1.4 / 2.0 / Автоматически / 2.1 |
| 5 | **Игровой режим (низкая задержка)** | переключатель | `g_video__vid_game_mode` | Отключает MEMC и шумоподавление |
| 6 | **ALLM (авто-игровой режим)** | переключатель | `g_video__vid_allm_switch` | Источник сам просит игровой режим |

**Изменения против завода:**
- EDID был **только для чтения** («Изменение недоступно до проверки обоих HDMI») — стал рабочим списком
- ARC добавлен и стоит сразу под CEC
- убраны пункты выбора приложения при включении (по просьбе владельца)

| Группа | Пункт | Тип | Что делает |
|---|---|---|---|

| | **Автофокус при перемещении** | переключатель | `persist.rjpj.autofocus.move` |
| **Коррекция изображения** | **Автокоррекция трапеции при перемещении** | переключатель | `persist.rjpj.autokeystone.move` |
| | **Коррекция четырёх углов** | действие | Заводской `KeystoneCalibrationActivity` |

### 4.9 Эквалайзер

| Пункт | Тип | Ключ | Что делает |
|---|---|---|---|
| **Пресет** | список | `projectorsoft_eq_preset` | Выключен / Ровный / Бас / Высокие / Голос / Пользовательский |
| **60 Гц** | слайдер −15…+15 дБ | `projectorsoft_eq_band_0` | Полоса 1 |
| **230 Гц** | слайдер | `projectorsoft_eq_band_1` | Полоса 2 |
| **910 Гц** | слайдер | `projectorsoft_eq_band_2` | Полоса 3 |
| **3,6 кГц** | слайдер | `projectorsoft_eq_band_3` | Полоса 4 |
| **14 кГц** | слайдер | `projectorsoft_eq_band_4` | Полоса 5 |

**Как работает:** используется `android.media.audiofx.Equalizer` с **глобальной сессией 0**.
Это значит эффект применяется к **любому** выходу — динамики, Bluetooth, HDMI. Заводской
эквалайзер писал в DSP MediaTek и по Bluetooth не работал.

Шаг слайдера — **1 дБ** (100 мБ). Значения показываются в дБ (`+3,0 дБ`).
Слайдеры редактируются только в пресете «Пользовательский»; в остальных показывают кривую.

Эффект **не освобождается** при выходе с экрана — пресет продолжает работать.

## 6. Сброс коррекции трапеции — как работает

Кнопка **«Сбросить все коррекции трапеции»** делает три вещи:

1. **Вызывает OEM-сброс нативно** — через `DexClassLoader` загружает
   `com.rjpj.tcorrection.KeystoneUtil` из `KeystoneCorrection.apk` и вызывает
   `getInstance().resetKeystone()`. Это внутри вызывает `writeParcelToFlinger(0)`,
   который **реально применяет** нули к дисплею.
2. **Пишет 8 углов** в `persist.rjpj.fourcorner.keystone_*` и `persist.display.keystone_*`.
3. **Проверяет чтением**, что все 8 значений стали `0`, и пишет это в лог.

**Почему нельзя только записать свойства:** нативное приложение читает свойства
`persist.display.keystone_*` только при старте или при вызове из своего экрана.
Без вызова `writeParcelToFlinger` картинка не менялась — это и был баг
«сброс работает только после захода в экран коррекции».

## 11. Технические ограничения (важно)

| Ограничение | Следствие |
|---|---|
| `versionName` не патчится | Всегда `1.0`; менять только `versionCode` |
| Сборка только в CI | Локально нет полного `android.jar` |
| Подпись только платформенная | Любой другой ключ — система откажет |
| `persist.trd.source_id` | Из приложения пишется только через `setprop` (SystemProperties не работает) |
| `getCurrentInputMethodInfo()` | Отсутствует в прошивке — только `Settings.Secure` |
| Температура LCD/LED | Недоступна без OEM-процесса |
| ARC/eARC | eARC вкл/выкл не существует как параметр |
| Переключение аудиовыхода | Не поддерживается платой |
