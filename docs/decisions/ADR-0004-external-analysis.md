# ADR-0004: Внешний сравнительный анализ — какие прошивки брать образцом

- Дата: 2026-11-23
- Статус: принято

## Контекст

Владелец предложил подсматривать идеи у сторонних прошивок. Touyinger ET32 (репозиторий
`Firmware-CN-Projectors`) признан **слабым кандидатом**: дpyгaя платформа (Android 9, `mt5862`/
`MTK9255`), собственные косяки, качество сомнительное.

## Решение

Приоритет источников для сравнительного анализа:

| Приоритет | Источник | Что ищем | Ограничение |
|---|---|---|---|
| 1 | Проекторы на **той же платформе** `mt5873_cd`/MT9660: Vidda, XGIMI, Wanbo, Everycom | реализация фокуса, трапеции, LED-яркости, меню проектора, маршрутизация кнопки Settings, thermal | ничего не прошиваем, только читаем и сравниваем |
| 2 | **Android TV / MediaTek телевизоры** на близкой платформе | Dolby Vision: конфигурация HWC, `kdrv_xc`, LUT, лицензионные файлы, тональный маппинг | DV требует лицензии и поддержки панели — см. Q-DV |
| 3 | AOSP / Android TV референс | штатные механизмы Settings, `HdmiControlManager`, media routing | переносится без ограничений |
| 4 | Touyinger ET32 | только как пример структуры OEM-служб | несовместим, ничего не переносим |

## Правила

1. Заимствуется **код/подход**, а не бинарники: чужие `.so`, `.ko`, калибровки не попадают в образ.
2. Любой перенятый приём сначала `STATIC_CONFIRMED` у источника, затем `DEVICE_VERIFIED` у нас.
3. Юридически: анализируем только публично распространяемые образы, не вскрытые платными сервисами.
4. Разбор чужой прошивки не блокирует основной путь — это параллельная исследовательская ветка.

## По Dolby Vision (Q-DV)

Признано «хотелкой» с низкой вероятностью успеха: у панели `maxLuminance=500`, в системе 0
DV-свойств, HWC `dv=false`. Даже при наличии DV-декодера в `libcodec2.MTK.so`/`mik.ko` нужен
лицензионный ключ и тонмаппинг. Исследование ведётся как отдельная задача после карты архитектуры,
без обещаний результата.
