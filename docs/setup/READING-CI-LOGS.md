# Как читать логи сборок GitHub Actions

Дата: 2026-11-26. Проверено на run 45701079530.

---

## Короткий ответ

**Права не нужны.** Логи читаются тремя способами, от простого к полному.

---

## Способ 1: страница шага (быстро, без файлов)

1. Открыть `https://github.com/MAX-TAC/Projector-Soft/actions/runs/<RUN_ID>`
2. В браузере кликнуть по нужному шагу (например «Compile Android 13…»)
3. Прочитать текст страницы

**Ограничение:** длинные шаги обрезаются, поиск неудобен.

## Способ 2: архив логов (полный, рекомендуется)

1. На странице run найти ссылку **«Download log archive»** —
   она ведёт на `https://github.com/<owner>/<repo>/suites/<SUITE_ID>/logs?attempt=1`
2. Открыть её в браузере → скачается `logs_<SUITE_ID>.zip`
3. Распаковать: внутри по файлу на каждый шаг
   ```
   0_build.txt
   1_Set up job.txt
   8_Compile Android 13 OEM-aware right-pane bridge.txt
   ...
   ```

**SUITE_ID** берётся из HTML страницы run (атрибут ссылки «Download log archive»).

**Это работает с cookies браузера** — токен не нужен.

## Способ 3: API (для быстрых точечных запросов)

```
GET https://api.github.com/repos/<owner>/<repo>/actions/runs/<RUN_ID>/jobs
```
Возвращает шаги и `conclusion` каждого. Не требует токена, но
**лимит 60 запросов в час** на IP без авторизации.

Аннотации с ошибками (самое ценное при падении):
```
GET https://api.github.com/repos/<owner>/<repo>/check-runs/<JOB_ID>/annotations
```
Поле `start_line` указывает **номер строки в workflow-файле**, где упало.

---

## Что НЕ работает и почему

| Способ | Проблема |
|---|---|
| `GET /actions/runs/<id>/logs` (zip через API) | требует токен с `actions:read` |
| Прямой `curl`/`Invoke-WebRequest` из PowerShell | песочница блокирует TLS: `schannel: SEC_E_NO_CREDENTIALS` |
| `api.github.com` из браузера без токена | лимит 60/час, потом 403 |

**Вывод:** архив через **кнопку на странице** (способ 2) обходит всё это —
браузер использует cookies, а не токен, и не упирается в лимит API.

---

## Практическое правило

При падении сборки:
1. Открыть run → **Download log archive** → скачать zip
2. Прочитать `0_build.txt` (там весь вывод) или файл упавшего шага
3. Если нужно точное место в workflow — аннотации по API (`start_line`)

Это быстрее, чем гадать по одному сообщению об ошибке.
