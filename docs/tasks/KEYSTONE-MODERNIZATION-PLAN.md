## 1. Что есть сейчас

**APK:** 2 301 421 B, 1 DEX (1.1 МБ), 3 экрана, **без служб**.

| Экран | Layout | Что делает |
|---|---|---|
| Main | `activity_main.xml` (404 B) | меню выбора |
| 4 угла | `activity_four_corner_correction.xml` (5 440 B) | коррекция четырёх углов |
| H/V трапеция | `activity_hvkeystone_correction.xml` (3 996 B) | горизонталь/вертикаль |
| Цифровой зум | `activity_digital_zoom.xml` (4 056 B) | масштаб |

**Графика:** `keystone.png` (718 КБ), `keystone_bg/up/down/left/right.png`,
`kst_arrow_*`, `kst_in_arrow_*`, `kst_in_center/round`, `adjust_key`,
`adjust_leftright_key`, `reset_key`, `select_point_key`, `menu_key`, `back_key`.

**Вёрстка:** все экраны — `ConstraintLayout` + `ImageView` (сетка + стрелки) +
`TextView` (подписи) + `Space` (отступы).

## 2. Проблемы текущей вёрстки

| Проблема | Следствие на 4K |
|---|---|
| Картинки только `hdpi-v4` | растягиваются, мыло |
| Фиксированный `textSize` | текст мелкий (шрифт не масштабируется) |
| Нет числовых значений | не видно, насколько сдвинут угол |
| Нет состояния «до/после» | непонятно, что изменилось |
| Нет сброса одним действием | нужно лазить в меню |
| Нет индикатора шага | не видно, сколько осталось до предела |

## 4. Технические изменения

| Что | Как |
|---|---|
| **4K-графика** | перерисовать `keystone.png` в 3840×2160, добавить `drawable-xxxhdpi` |
| **Текст** | использовать `sp` вместо фиксированного размера, база 24sp |
| **Сетка** | рисовать программно (`Drawable`/`View.onDraw`), а не PNG — резкость в любом разрешении |
| **Числовые значения** | брать из `persist.display.keystone_*` / `persist.sys.offset_*` |
| **Чтение состояние** | через `TrdSystemService` (`IMotorCtrl`, `IProjectorCtrl`) |
| **Сброс** | `SetKeystoneReset()` из `trd.framework` |

---

## 5. Порядок работы

1. **Прототип вёрстки** — собрать три экрана на новом `ConstraintLayout`, без логики.
2. **Подключить чтение состояния** — числа из `persist.*` и `trd.framework`.
3. **Подключить запись** — стрелки и ползунки пишут через `trd.framework`.
4. **4K-графика** — перерисовать или заменить на программную отрисовку.
5. **Тест на устройстве** — сравнить старое и новое поведение.

---

## 6. Что НЕ трогать

- Логику `trd.framework` — она работает
- Классы коррекции из `com.android.tv.settings` — там OpenCV-гомография
- Сброс трапеции при смене режима — это делает система

## 7. Открытые вопросы

| Вопрос | Как выяснить |
|---|---|
| Откуда брать текущие координаты углов? | `persist.display.keystone_*` — есть 8 ключей, проверить на устройстве |
| Есть ли пределы у углов? | В коде приложения или в `trd.framework` |
| Зум активен всегда или только в определённом режиме? | Проверить на устройстве |
| Как отображается оверлей во время регулировки? | Рисует `com.trd.service.UICtrlImpl` — не мешать |
